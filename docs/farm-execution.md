# Farm execution contract

Only persisted, enabled numeric competition targets enter the fixed endpoint broker. The Linux adapter currently accepts non-loopback unicast IPv4 TCP and UDP endpoints; IPv6 fails closed. Dependencies are bubblewrap, iproute2 and an operator-delegated cgroup v2 subtree. There is no unsandboxed fallback. Runtime and upload snapshots must be private Core-owned directories. Core/checker configuration and secrets are not mounted or inherited by workers.

`per_target` invokes one transient worker at a time, with `TARGET_HOST` and `TARGET_PORT`. `batch` invokes one worker with all selected targets. Both modes receive `TARGETS_JSON`, a JSON array of objects `{ "id": "team-a", "address": "192.0.2.10:9000", "transport": "udp" }`. In batch mode `TARGET_HOST` and `TARGET_PORT` identify only the first target; use the JSON list for all destinations. No worker-provided address is accepted by the parent broker. The manifest timeout is an aggregate deadline for the entire run, including all per-target invocations.

Per-target stdout and stderr undergo configured flag extraction. Batch attribution requires one JSON object per line on either stream: `{"target_id":"team-a","flag":"FLAG_VALUE"}`. Values must match the configured regex in full, and the target must belong to the persisted run. Other lines remain diagnostic logs and do not create captured flags. Capture audit records use the system actor and preserve the user who initiated the run. Keep flag lines near the end: each stream retains a bounded 32 KiB tail; loss is reported in the stored logs. Aggregate stored stdout and stderr each have a 64 KiB cap.

UDP datagrams retain message boundaries through length-prefixed Unix streams. Each endpoint has up to sixteen source sessions, each with an eight-datagram queue and a thirty-second idle lifetime. Queue/session overflow drops datagrams with an explicit worker diagnostic. Across all targets the parent admits at most sixteen broker connections. Each connected upstream UDP socket has one fixed allowlisted destination. There is no destination-selection protocol, routing interface or DNS inside the worker. Batch selections containing target aliases with duplicate address/transport endpoints are rejected explicitly during exploit configuration and again before sandbox launch.

`POST /api/v1/farm/runs/{id}/retry` requires `Idempotency-Key` and a completed, failed, timed out, cancelled or interrupted origin run. It creates a new queued attempt with `origin_run_id`, the origin version/manifest/target selection and the retrying authenticated user. Enabled exploit and targets are checked again. Reusing the same key returns the same attempt; a changed origin or user conflicts. Original history and logs remain unchanged. A Core restart marks running attempts interrupted; it does not replay them. Cancellation persists immediately and signals the active worker.

Validation during implementation deliberately excludes uploaded exploit execution, sandbox execution and outbound target tests. Safe checks cover compilation, command/config validation, SQLite transitions and in-memory UDP framing only. Kernel isolation and network behavior therefore require a separately authorized operator integration run; existing opt-in tests remain ignored.
