# Farm integration

`Farm::open(auth, private_upload_directory, Arc<dyn Runner>)` migrates schema versions 8 and 13 and marks previously running work interrupted. Queued runs survive restart. Retrying a terminal run through POST runs/{id}/retry creates an origin-linked attempt with a new idempotency key; no external execution is silently replayed. Start `farm.clone().background(shutdown)` once. Worker concurrency is one.

`Runner::run(Job, CancellationToken)` returns a Send boxed future of `anyhow::Result<RunOutput>`. The job contains immutable artifact path, manifest, resolved enabled numeric-IP targets, enabling/requesting user, and run/version/exploit IDs. The adapter must honor manifest mode: per_target runs each target sequentially with individual captured provenance; batch runs once with all selected targets. The scheduler's timeout is an aggregate run deadline (manifest timeout plus five seconds of sandbox teardown allowance), including all per-target executions. The sandbox adapter must stop children on cancellation or future drop. UnavailableRunner always fails closed. Only the sandbox runner may produce a succeeded result; uploading/configuring/enqueuing never produces execution success.

API uses bearer authentication under `/api/v1/farm`: GET/PUT targets and exploits, DELETE targets/{id} and exploits/{id} with revision query, GET exploits/{id}/versions for bounded immutable version metadata, PUT exploits/{id}/versions/{version} with opaque application/octet-stream body, GET/POST runs, GET runs/{id}, POST runs/{id}/cancel and POST runs/{id}/retry. PUT revision 0 creates and matching current revision updates. A run POST body has exploit_id and revision and requires Idempotency-Key. Reusing a key with different actor/exploit/revision fails. GET collections use exclusive `after` ID cursors, 100 entries maximum. Logs are only returned by the audited run detail read.

Targets accept IP literals only, nonzero ports, and tcp/udp. Enabled target IDs are checked at configuration, enqueue, and execution. Unknown request fields are rejected. Author/initiator comes from authentication. Every write and diagnostic read appends audit in its SQLite transaction. Deleting an exploit preserves immutable versions/run history; deleting or disabling a target prevents queued execution that needs it. Already-running jobs retain their admitted target snapshot.

Bounds: 1024 targets, at most 256 distinct targets per exploit, 64 exploit records, 256 immutable uploads, 2 MiB each, 5000 total run history rows (admission fails when full), 100 list rows, 64 KiB retained per output stream, timeout 1–120 seconds, memory 32–256 MiB, CPU 10–100%, interval 10–86400 seconds or manual. Uploads are individual private opaque files, with server-computed SHA256; no archives are expanded. Version files are retained until explicit operator maintenance; there is no automatic destructive cleanup. Farm uses one locked private storage directory and no persistent worker daemon.

Focused validation: `cargo test -p hydra-core --lib modules::farm`; tests cover actual SQLite audit/queue persistence, allowlist/revision/idempotency/immutable version rejection, disabled targets, cancellation and unavailable sandbox failure. `python3 tests/e2e/operations.py` passed against real Core and Proxy binaries with a real local HTTP checker: management/upload/idempotency, fail-closed unconfigured sandbox, manual capture/redaction/accepted submission, and durable restart (2.14 seconds). This does not claim sandbox execution acceptance. RAM/CPU measurements are pending system integration.

Current execution, UDP framing, structured batch capture and retry semantics are detailed in [farm execution](farm-execution.md). The focused safe retry test never invokes a runner; kernel and target execution tests remain excluded from the current validation.
