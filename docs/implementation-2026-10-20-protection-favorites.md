# Per-service protection, live charts and traffic favourites

User requirements: protect authorized A/D services from overload even when clients share a source IP; configurable limits per service, charts of connections/active streams/traffic/rejections, and favourite streams whose retained contents survive normal rotation.

## Decisions and shared interfaces

- Extend the existing two-process design; no IP bans, extra daemon or per-connection OS threads.
- Existing services retain current behaviour unless protection is enabled. `Service.protection` is an optional `ServiceProtection`, default null. Its fields are `max_active_flows` (recommended 128), `tcp_connections_per_second` (50), `udp_datagrams_per_second` (1000), `bytes_per_second` (8388608) and `idle_timeout_ms` (30000). Zero disables a rate only; active-flow and timeout fields must be positive. One second of tokens is the burst allowance. A single datagram/read bigger than a configured byte burst is rejected. Shared global flow cap remains.
- Per-service stable limiter state survives config edits without refilling tokens; enforce before decoder, scanner, capture and upstream creation. TCP closes whole connections on admission/byte overflow, UDP drops whole datagrams; ordinary admitted byte streams stay unchanged. No wait queues. A budget covers a service's clients collectively; identity/fairness behind the shared IP is unavailable. Kernel SYN and saturated link protection remain outside a userspace relay's capability.
- Proxy status adds `service_metrics`: repeated objects containing `service_id`, `active_flows`, `accepted_flows`, `rejected_flows`, `bytes_client_to_server`, `bytes_server_to_client`, `dropped_datagrams` and `rate_limited`. Counters are cumulative within a proxy epoch. Core exposes these at its existing authenticated status endpoint. No per-denial event/audit flood; configuration changes retain normal audit provenance.
- Live chart polls authenticated Proxy status every 2s while visible, retains at most 120 points per service, distinguishes offline/gaps/epoch resets, shows active sessions, accepted/new and rejected connections per second, bytes/s both directions and UDP drops/s. Use actual elapsed time, service colours, accessible SVG and textual latest values. It is a recent view since opening the page, not a promised historical monitoring database.
- Favourite mutation: authenticated audited `PUT /api/v1/traffic/flows/{id}/favorite` with `{ "favorite": true|false }`; flow list/detail adds `favorite: boolean`; list query supports `favorite=true`. Protect captured raw history in Proxy as well as flow metadata/decoded data in Core. Saving must not claim success when raw pinning fails, but an already unavailable capture may be saved with explicit unavailable status.
- Pin active flows before completion as well as closed flows; a pending favourite must survive restart. Normal TTL/quota rotation must exclude favourites. A separate bounded archive with no automatic favourite eviction is required; reject new pins visibly at capacity. Keep the existing bounded capture tail and UDP datagram semantics. Keep decoded retention bounded and surface any incomplete capture explicitly. Removing a favourite returns it to normal rotation; never delete an unrelated favourite to free space.
- Preserve the uncommitted CI zstd test fix and user-owned untracked directories. Do not commit/push unless asked. Generate OpenAPI/frontend snapshots once after backend work; no hand edits to generated outputs.

## Tasks and file ownership

1. Protection backend: domain protection type, service REST validation, wire conversion and additive protobuf fields for service protection and metrics, Proxy limiter/transport integration/status, Core status projection. Own these files; coordinate shared protobuf additions with favourites task.
2. Favourites backend: Core traffic modules/migration, Proxy history/grpc diagnostics, additive favourite RPC/wire messages. Preserve metadata/decoded data/raw history across ordinary rotation and restart; authenticated audit/idempotency/capacity errors. Do not touch protection code. Coordinate protobuf separate sections.
3. Limits and chart frontend: ServiceForm and new protection component, new service metric chart components/data transforms on Services page. Use interfaces above. Do not change traffic favourites UI or generated contracts.
4. Parent: favourites Traffic UI, integration, docs, generated contracts and bounded localhost verification. Preserve previous CI fix. Inspect and address cross-task issues before reporting.

## Validation

Use small deterministic limiter tests and harmless localhost two-process checks: same-IP clients across services, active cap/release, rate reset without token refill, TCP binary integrity, UDP datagram/zero-length integrity and counters; no stress test against competition or public infrastructure. Favourite tests must force count/byte/TTL rotation and restart, preserving raw plus decoded data, exercise active pin and unpin, quota refusal and auth/audit. Run package tests, fmt/clippy, architecture/contracts generation checks, Vue tests/typecheck/build, and relevant E2E tests. Deployment must use existing scripts and retain rollback if remote tools are available.
