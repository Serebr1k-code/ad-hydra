# Control integration

Export `modules::{services,filters}`. `services::Control::open(auth_state).await` runs numbered migration2 through the Core DB owner. `services::router(control.clone())` exposes services/filter REST. `services::ControlApi::openapi()` merges handlers/schemas.

Control desired is one global monotonic optimistic revision: `desired().await?` returns `Desired { services:ServiceSnapshot, rules:RuleSnapshot, applied_revision, services_applied_revision, rules_applied_revision, apply_error }`. Both snapshot revisions advance on either mutation, making cross-reference validation transactional. Send services then rules; call `mark_services(revision, Option<String>)` and `mark_rules(...)` only after real Proxy ACK. `changed:Arc<Notify>` wakes reconcile; initial reconcile should always call desired before waiting. `observe_hit(rule_id:String)` increments saturating stored counters. No per-packet DB use.

Every mutation takes expected_revision and returns409 on stale global revision. IDs generated by HTTP server, client author fields rejected. Creators/last editors stored from verified actor; list includes epoch UTC dates, counters, desired/applied revision and status; applied_enabled null while unacknowledged. Queries `after` exclusive ID cursor, `limit`1..100, optional bounded `q`. PATCH accepts complete validated entity fields, not merge patches. DELETE takes expected_revision query parameter. Rule/service references validated by pure compiler in same mutation transaction; deleting referenced service fails.

New filters must begin shadow. POST `/api/v1/filters/{id}/test` with `{"fields":{...typed domain fields...}}` evaluates supplied saved fields in shadow without forwarding and records fingerprint. Switching mode to enforce requires exact fingerprint (enabled/mode excluded) tested first. This is explicit test evidence, not proof of safety; saved traffic storage arrives Phase3. Rule fields are domain Expression/Action types; OpenAPI currently represents domain AST objects without detailed union schemas.

Proxy apply audit is system/service; original user provenance remains mutation audit in DB. Audit logs revisions/counts only, avoiding sensitive filter literals. Limits:128services,256rules,1MiB combined serialized snapshot,100 list records; state ACK is aggregate per kind not per entity. Existing Phase1 CLI snapshots need parent import on first Core boot; otherwise DB initially empty. Parent owns startup, reconcile and protected docs.

Bootstrap now wired in `app.rs`: CLI global `--database`, `--key`, `create user <username> [password]`, `serve --origin https://host[:port]`. Serve opens owned private DB dir and protected key, runs migrations, seeds optional `--snapshot` only when DB empty. REST body limit256KiB, 32 concurrent requests, 30-second request timeout. API docs remain trusted loopback so keep reverse-proxy docs routes restricted. `api::router(view,auth,control)`, `api::openapi_document()` merge all real routes; status verifies session and audits read. `reconcile` parent signature must take control as final5th argument.
