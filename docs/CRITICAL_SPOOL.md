# Critical event spool

Proxy telemetry uses a private directory containing `events.bin`, an atomic snapshot of unacknowledged critical FlagFinding/EventLoss protobuf events. Each event has one critical EventBatch and a contiguous sequence starting at 1. The spool epoch remains stable across proxy restarts until the spool directory is deliberately removed; it is independent of the process status epoch. A mismatched stream epoch replays all outstanding events. ACK requires the exact spool epoch and cannot exceed the last committed sequence. Core must commit its deduplicated records before ACK. ACK snapshots are synced before success; a failed ACK write preserves the old replay set. If directory fsync fails after atomic replacement, durability is uncertain: the spool refuses subsequent replay/ACK/appends until restart rather than diverging sequence state.

A single disk thread serializes fsync, atomic replacement, replay, and ACK commands. Transport calls `try_emit` only: a successful call means acceptance into a bounded 64-entry memory queue, not persistence. A crash can lose queued events not yet committed. Replay includes only events whose snapshot write completed. Critical flags must never also be emitted onto the normal telemetry stream.

Each event is limited to 64 KiB. Live spool quota is 2 MiB; atomic replacement can require another 2 MiB, keeping directory file content below 4 MiB. The event queue holds at most 4 MiB of encoded event payload, plus bounded Rust object overhead. Directory permissions are 0700, new files 0600. One proxy process exclusively owns the directory. Corrupt/oversized persistent data fails startup rather than silently discarding unacknowledged findings.

Overflow, oversize events, invalid payload kinds, and disk failures increment an atomic drop counter and aggregate a critical loss event. Pending losses retry every 100 ms and after commands; they can only persist when disk and quota permit. The in-memory pending count itself may be lost on process/power failure, so this is finite durability rather than unlimited guaranteed delivery. Spool I/O errors log only error kinds, never flag values. Exhausted storage preserves existing unacknowledged events; it does not overwrite them.

Management replay and ACK use the same bounded queue and return WouldBlock when saturated. Callers reconnect/retry; they must not interpret this as ACK success. Replay batches are limited to 256 events per call and the total live spool bytes. Consumers should paginate and use a bounded gRPC send queue. Dropping the final spool handle drains accepted commands and joins the disk thread; app shutdown should release transports first.

Run `cargo test -p hydra-proxy --test critical_spool` for real-file restart, ACK, bounds, and loss checks. Disk snapshot rewriting deliberately favors simple bounded correctness over high critical-event throughput; no throughput or RSS guarantee has been measured.
