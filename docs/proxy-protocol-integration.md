# Proxy protocol lifecycle

`Protocols::open(directory).await` loads and checksum-validates at most sixteen immutable plugin versions and 256 service activations. Directory mode is 0700; module and manifest files are 0600. Writes use a temporary file, file fsync, atomic rename and directory fsync. Install writes module before publishing the manifest; activation publishes the manifest before replacing the in-memory map. A crash can leave an unreferenced module, never a published manifest pointing to a partially written module. Startup removes unreferenced `.wasm` files and the pending file in this dedicated directory. A directory fsync failure after rename logs uncertain crash durability and retains the committed in-memory state. Invalid persisted files fail startup explicitly.

`install(id, version, sha256_hex, Vec<u8>)` validates names and <=4 MiB size, verifies SHA-256, compiles and validates ABI/imports/resource limits through the runtime. Versions cannot be overwritten. `activate(service_id, id, version)` requires an installed version. Caller must validate the configured service and provide authenticated audit provenance. Runtime has no Core or database dependency.

A single nonqueued mutation/compile semaphore returns a busy error for concurrent lifecycle operations. Compilation, persistence and in-memory publication run in one blocking task retaining the permit, so cancellation of the calling RPC cannot release the slot while writes continue. No lock is held during compilation or file I/O. Other application instances must not open the same private directory concurrently.

`version_for(service_id)` clones the active Arc. `session(service_id, protocol_id)` uses that activation in preference to the configured profile; otherwise `http`, `http1`, and `http1.1` create the native request decoder, and other names create raw passthrough. Existing sessions retain old versions. No per-read control-plane operation occurs.

`ProtocolSession::feed(direction, bytes)` delegates metadata decoding; `http_mut()` allows access to complete native HTTP request frames; `is_wasm()` signals an active plugin override. Eight global WASM session permits cap live-flow guest linear memory at 32 MiB plus one transient 4 MiB validation instance, compiled modules, engine bookkeeping, and bounded buffers; actual RSS is unmeasured. Saturation returns an error: the caller must emit loss/failure telemetry and choose raw passthrough or explicitly configured close policy. Drop the entire lease when a flow ends or decoder is disabled. The decoder is private so a guest instance cannot escape its permit.

There is currently no uninstall or deactivate RPC, no signed publisher authentication, and no Rust WASM target available in this development environment. Lifecycle tests load actual WAT-generated WASM; the Rust sample build remains a documented prerequisite.
